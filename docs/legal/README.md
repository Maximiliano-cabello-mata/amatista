# Amatista — expediente documental de autoría y evidencias

**Estado:** carpeta pública de organización documental, abierta el 29 de octubre de 2026 (hora de México).
**Proyecto:** [Amatista](https://github.com/Maximiliano-cabello-mata/amatista), plataforma educativa 3D.
**Propósito:** reunir referencias verificables del desarrollo y establecer el procedimiento para conservar evidencias de autoría, versiones y componentes originales.

> **AVISO DE CONFIDENCIALIDAD:** Este repositorio es **PÚBLICO**. Aquí solo van referencias, índices y plantillas sin información confidencial. **No agregar** identificaciones oficiales, firmas, CURP, domicilios, contratos, comprobantes, datos de alumnos, cuentas, respaldos Oracle, archivos `.env`, llaves SSH, tokens ni código fuente privado. El expediente material y las copias de preservación deben almacenarse en un **repositorio independiente PRIVADO**, con copia cifrada fuera de GitHub. Una rama de un repositorio público **no** es privada.

## Cómo usar el expediente

- En cada corte significativo del proyecto, registrar el **SHA completo del commit**, fecha UTC, rama y versión observada; enlazar el commit y la documentación correspondiente.
- Conservar, **fuera de este repositorio público**, una copia del código original que se pretenda acreditar, archivos exportados, comprobantes, capturas auténticas y un manifiesto SHA-256. No añadir secretos ni datos personales en esos paquetes.
- Documentar por separado el código original, las bibliotecas externas, recursos gráficos, contenidos educativos y aportaciones ajenas. No atribuirse derechos sobre obras de terceros.
- Conservar comprobantes originales de trámites y respuestas de autoridad en el archivo privado.
- Registrar todo cambio de custodia o corrección mediante una entrada fechada; no sobrescribir silenciosamente evidencias anteriores.
- Hacer respaldos cifrados y comprobaciones periódicas de integridad.

## Límites de esta carpeta

Esto **no equivale** a una inscripción en INDAUTOR, a un registro de marca ante el IMPI, a una certificación notarial, ni demuestra por sí solo la titularidad exclusiva del software. Un commit o una captura pueden apoyar una cronología técnica; la acreditación jurídica depende de las circunstancias, contratos y la evaluación correspondiente.

La decisión sobre la licencia general del repositorio sigue pendiente en el README; el add-on declara una licencia GPL-3.0-or-later en su manifiesto. No se cambia ninguna licencia al crear este expediente.
