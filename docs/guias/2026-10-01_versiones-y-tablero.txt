2. CÓMO CREAR LOS TAGS
-----------------------------------------------------------------------------
Desde la raíz del repositorio oficial (clon completo, no superficial):

    bash herramientas/crear-tags.sh --reemplazar-v0.2.0
    git push origin --tags
    git push origin :refs/tags/v0.2.0      # quita el tag viejo de GitHub

- Cada tag lleva la fecha de su commit, no la del día en que se crea.
- Si git tiene configurada la firma SSH (user.signingkey), los tags se firman.
- Se puede ejecutar varias veces: los tags que ya existen se saltan.

Estado: publicados el 2026-10-01. Los cuatro tags están firmados con SSH
(verificados en GitHub) y v0.2.0 ya se quitó del remoto.

Opcional: en GitHub → Releases → "Draft a new release", elegir cada tag y
pegar su sección del CHANGELOG.md.

3. REGLA PARA LAS PRÓXIMAS VERSIONES
-----------------------------------------------------------------------------
  MAYOR (v3.0.0)   Cambio de fase del producto (por ejemplo el 3D Lab).
  MENOR (v2.1.0)   Una meta del roadmap terminada (ver KANBAN.md).
  PARCHE (v2.0.2)  Solo correcciones.

Al cerrar una versión:
  1. Pasar las notas de "Sin publicar" a una sección nueva en CHANGELOG.md.
  2. git tag -s v2.1.0 -m "v2.1.0 — Oracle en producción"
  3. git push origin v2.1.0
