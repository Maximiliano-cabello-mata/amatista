# Sentry: errores del backend y de la PWA

31 de octubre de 2026 · T-184 (código) y T-185 (configurarlo) · **sin SQL** · Sentry viene en el GitHub Student Developer Pack.

## 1. Qué hace

Cuando algo falla en la API o en la PWA, Sentry guarda el error con su traza, la versión y el commit sospechoso. Con la integración de GitHub, cada error se puede convertir en un issue del repositorio, que es lo que Claude puede leer y arreglar.

- **Sin DSN no pasa nada.** El backend no inicia Sentry y la PWA ni siquiera descarga el SDK: vive en su propio trozo (`sentrySdk-*.js`, unos 120 KB comprimidos) que no se precachea. Los alumnos con pocos datos no pagan por él.
- **Nunca se envían datos personales.** `send_default_pii` está apagado y además `backend/observabilidad.py` y `frontend/src/lib/sentry.js` quitan el usuario, la IP, las cookies, `Authorization`, `X-Sesion-Id`, la huella del add-on, `X-Forwarded-For`, la consulta de la URL y el cuerpo de las peticiones (contraseñas, escenas de Blender). En la PWA tampoco se guardan migas de lo que se escribe en los formularios.
- **Solo errores por defecto.** Las trazas de rendimiento del backend se encienden a mano (`SENTRY_TRAZAS`). La PWA no manda trazas ni graba la pantalla.

## 2. Variables

| Dónde | Variable | Valor |
| --- | --- | --- |
| VM, `backend/.env` | `SENTRY_DSN` | DSN del proyecto **amatista-backend** |
| VM, `backend/.env` | `SENTRY_ENTORNO` | `produccion` (por defecto) o `staging` |
| VM, `backend/.env` | `SENTRY_TRAZAS` | `0` (solo errores) a `1`; `0.1` mide 1 de cada 10 peticiones |
| Cloudflare Workers Builds (variable de compilación) | `VITE_SENTRY_DSN` | DSN del proyecto **amatista-web** |
| Cloudflare Workers Builds | `VITE_SENTRY_ENTORNO` | `produccion` |

El DSN no es una contraseña (la PWA lo publica en su código), pero igual va en `.env` y en Cloudflare, nunca en el repositorio.

## 3. Pasos (los hace el creador, T-185)

1. En sentry.io, **Create project › FastAPI**, nombre `amatista-backend`, producto **Error monitoring** (y **Tracing**, que queda apagado mientras `SENTRY_TRAZAS=0`). Copia el DSN.
2. **Create project › React**, nombre `amatista-web`, solo **Error monitoring**. Copia el DSN.
3. **Settings › Integrations › GitHub** › conectar `Maximiliano-cabello-mata/amatista` (código en las trazas, commits sospechosos y crear issues).
4. En la VM:
   ```bash
   cd /home/opc/amatista && git pull
   backend/venv/bin/pip install -r backend/requirements.txt   # trae sentry-sdk
   nano backend/.env        # SENTRY_DSN=https://…@….ingest.sentry.io/…
   sudo systemctl restart amatista-backend
   journalctl -u amatista-backend -n 20 | grep -i sentry   # «Sentry activo (entorno produccion)»
   ```
5. En Cloudflare › Workers & Pages › amatista › Settings › Build › Variables: `VITE_SENTRY_DSN` y volver a desplegar.
6. Prueba: en la consola del navegador de `amatista-3d.tech`, `setTimeout(() => { throw new Error('prueba Sentry') })`. El error debe aparecer en `amatista-web` **sin** usuario, IP ni cookies.

## 4. Plan gratis

El plan Developer de Sentry (y el del Student Pack) tiene una cuota mensual de errores. Para no gastarla: deja `SENTRY_TRAZAS=0` salvo cuando estés midiendo algo, y en **Settings › Spike Protection** déjala encendida.
